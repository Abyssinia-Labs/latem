## What changed

**latem installs with Homebrew**, on macOS and Linux:

```sh
brew install abyssinia-labs/tap/latem
latem setup
```

It is the same signed archive `install.sh` downloads. The tap checks each
release's checksums against latem's signing key before it writes them into the
formula, and Homebrew checks the download against those checksums.

A Homebrew install is updated by Homebrew, and this release makes latem behave
that way (RUNNER_SPEC A78):

- **`brew upgrade latem` updates it**, and the running agent moves onto the new
  version by itself at the first moment no build is in flight. It never stops
  taking work to make that moment.
- **The service starts Homebrew's link** (`/opt/homebrew/opt/latem/bin/latem`),
  not the versioned directory the next `brew upgrade` deletes.
- **`latem update` refuses** to write into Homebrew's directory and says to run
  `brew upgrade latem` instead. The once-a-day notice says the same.
  `agent.auto_update` does nothing on a Homebrew install, and `latem doctor`
  warns when it is set.

### Upgrading from v0.3.0

Nothing to do for a machine installed with `install.sh`: `latem update` works as
before.

To move a machine to Homebrew, install it, point the service at Homebrew's
binary, and remove the old one so the shell finds the new one:

```sh
brew install abyssinia-labs/tap/latem
"$(brew --prefix)/bin/latem" service install
rm ~/.local/bin/latem
```

`service install` rewrites the service and restarts the agent, so run it while
the machine is idle.
