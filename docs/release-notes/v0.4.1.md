## What changed

**`latem doctor` no longer warns that the agent runs an old `config.toml`
after an update** (RUNNER_SPEC A80). `latem update` and SIGUSR2 move the agent
onto a new binary in place, keeping its process id, and the new binary reads
the config afresh. doctor compared the file with when that process first
started, so after any such switch it warned, and told you to restart an agent
that was already running the file. The agent now records when it read the
config, and doctor compares with that.

### Upgrading from v0.4.0

- **Installed with `install.sh`:** run `latem update` once.
- **Installed with Homebrew:** run `brew upgrade latem`. The running agent
  moves onto the new version by itself at the first moment no build is in
  flight.

The warning goes once the agent runs v0.4.1: doctor needs the time the new
agent records, so a newer `latem` command alone does not clear it. Nothing
else changes, and the wire protocol is still 2.7.

Coming from v0.3.x, run `latem update` twice, as the v0.4.0 notes say: the
first run installs v0.4.1 and the second adds `ltm`.
