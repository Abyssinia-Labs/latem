## What changed

**A job that calls a workflow in its own repository runs** (RUNNER_SPEC A82,
protocol 2.8). `jobs.<id>.uses: ./.github/workflows/package.yml` is planned as
that workflow's jobs, inside the caller's run, and each is named as GitHub
names it: `release / pack`.

- `with:` is checked against the called workflow's `on.workflow_call.inputs`:
  types, required inputs and defaults, as GitHub checks them.
- `secrets:` takes `inherit`, or one `${{ secrets.NAME }}` per name. A literal
  value is refused.
- The called workflow's `outputs` reach the caller's `needs`, and its jobs'
  results decide the caller's, as on GitHub.
- A called job's token can be narrower than its caller's, never wider.
- Calls nest three deep. A cycle, or a fourth level, is refused by name.
- `latem workflows check` and `latem try` take a job path: `latem try
  release/pack`.

Still refused, each by name: a workflow from another repository, a local call
with `@ref`, `strategy:` or `concurrency:` on the calling job, and
`concurrency:` on the called workflow.

**`latem run` follows the build when you are watching** (A81). At a terminal,
a bare `latem run myapp test` now prints the run id and then its log, and exits
with the run's result, as `--follow` does. `--detach` queues the run and exits,
as before. A script is unaffected: when stdout is not a terminal, it gets the
id alone and exit 0 for a queued run.

**The README is a quickstart.** The reference that was in it is now in `docs/`:
install, jobs, configuration, secrets, doctor and commands.

### Upgrading from v0.4.1

- **Installed with `install.sh`:** run `latem update` once.
- **Installed with Homebrew:** run `brew upgrade latem`.

Either way, the running agent moves onto the new version at the first moment
no build is in flight.

**The wire protocol is 2.8**, and latem.dev already speaks it. A v0.4.x
machine keeps working as before. Jobs from a called workflow go only to 2.8
machines, so update every machine that takes such a repository, or those jobs
wait for one that can run them.

**At a terminal, `latem run` with no agent running now exits 3** and queues
nothing, where it used to queue the run and exit 0. Add `--detach` to queue it
for an agent that starts later.

Coming from v0.3.x, run `latem update` twice, as the v0.4.0 notes say: the
first run installs v0.5.0, and the second adds `ltm`.
