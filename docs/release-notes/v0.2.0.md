## What changed

**latem now runs your GitHub Actions workflows as they are written.** v0.1.x ran
the jobs in `.latem/jobs.yaml`; v0.2.0 also plans and runs `.github/workflows`,
on your own machines, under GitHub's runner contract: `strategy.matrix`,
`actions/checkout`, JavaScript and composite actions, `GITHUB_ENV` and
`GITHUB_OUTPUT`, `${{ secrets.* }}` and `${{ vars.* }}` answered on the machine,
and a check on the commit when the job ends. `.latem/jobs.yaml` works as it did.

This is the first release since the repository went public, and the first that
`install.sh` hands a stranger that does anything useful with
[latem.dev](https://latem.dev).

### Upgrading from v0.1.x

**The wire protocol is 2.7, and v0.1.x speaks 1.0.** A control plane sends
workflow jobs only to an agent that says 2.0 or later, so a v0.1.x machine
connects and is never given one. Upgrade every machine:

```
curl -fsSL https://raw.githubusercontent.com/Abyssinia-Labs/latem/main/install.sh | sh
latem setup
```

`setup` keeps the `config.toml` you have, and rewrites the service definition
when it is an older revision, which restarts the agent. From here on,
`latem update` installs a release and moves a running agent onto it without
cancelling a build.

### Setting a machine up

- **`latem setup`** walks from a fresh install to a working machine: config,
  the repositories it builds, the toolchains their jobs need, registering in
  the browser, the service, and `doctor`. On a terminal it is a screen showing
  what this machine can build and what is in the way, and it installs what you
  agree to. It never runs `sudo` and never accepts a licence for you.
- **`latem repo`, `latem secrets`, `latem vars`** edit the config and the
  secret stores, and tell the running agent. `latem secrets copy --to HOST`
  moves a value to another machine over ssh, on stdin, never in an argument.
- **`latem workflows check --repo R`** says what each job needs of a machine and
  what this one lacks, read from the repository without a checkout.
- **`doctor`** checks what your jobs need rather than everything a Mac could
  need, and warns where a runner's labels promise a toolchain it does not have.

### Running

- **A machine needs no GitHub login of its own.** A plan and a job bring a
  read-only token for the repository's fetches, so a machine that reboots to
  its login screen still builds.
- **A docker runner's default image is `ghcr.io/abyssinia-labs/latem-ubuntu`**,
  pinned by digest, instead of a placeholder you had to replace.
- **Each runner is sized to the machine** (`capacity`), and a machine's
  heartbeat says what it can build and what is in the way, which the app shows.
- **macOS updates and Xcode updates are survived**, not just tolerated: the
  agent notices a changed toolchain and recovers.

### Security

The threat model is unchanged and `test/invariants` still enforces it. Two things
worth knowing now that the repository is public: a pull request from a fork is
never planned or built on your machines by the control plane, and latem's own CI
runs on GitHub's runners, never on anybody's machine. Report a vulnerability
through the Security tab, as `SECURITY.md` describes.
