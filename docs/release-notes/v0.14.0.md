## What changed

**latem vault is now PinkVault, and latem finds it under its new name**
(RUNNER_SPEC A113). PinkVault is the vault's final name. Its command is
`pinkvault`, `pink` for short, and it keeps its data in `~/.pinkvault`. This
release has to be on a machine before that machine moves to PinkVault 0.7.0,
because 0.7.0 moves the vault's folder on its first run.

- **Finding the vault:** latem looks for `pinkvault`, then `latem-vault`, then
  `openvault`. It looks on `PATH`, in cargo's bin and in Homebrew's.
- **Reading it:** latem reads the vault's socket from `$PINKVAULT_HOME`, then
  `~/.pinkvault`, before the older homes (`$LATEM_VAULT_HOME`,
  `~/.latem-vault`, `$OPENVAULT_HOME`, `~/.openvault`).
- **`latem vault …`** runs `pinkvault`, or the older command where that is
  all a machine has.
- **Installing it:** `latem setup` installs it from
  `abyssinia-labs/tap/pinkvault` once the tap has that formula. Until
  PinkVault 0.7.0 is in the tap, setup installs `abyssinia-labs/tap/latem-vault`,
  which stays as an alias for one release.
- **Messages:** what latem tells you to type names the command it found on
  your machine, and `pinkvault` when it found none.

## Upgrading from v0.13

- **Installed with `install.sh`:** run `latem update` once.
- **Installed with Homebrew:** run `brew upgrade latem`.

Either way, the running agent moves onto the new version at the first moment no
build is in flight.

**Nothing changes on your machine until you move it to PinkVault.** A machine
on latem-vault 0.6.0 keeps working as before. These stay as they are:

- `[secrets] vault = true`
- the store name `vault`
- the readiness items `vault-…` and the doctor checks `vault.*`

The names `latem-vault` and `openvault`, their folders and their variables
work for one more release after PinkVault 0.7.0.
