## What changed

**A multi-line secret in the macOS Keychain resolved to hex, not to a key.**
This is the reason to upgrade, and it was silent in every diagnostic latem
offers.

`security find-generic-password -w` prints any value containing a byte outside
printable ASCII — a newline above all — as bare hex digits, with nothing marking
that it did so. v0.1.0 passed that through unchanged, so an
`APP_STORE_CONNECT_KEY_P8` stored in the Keychain resolved to the literal string
`2d2d2d2d2d424547494e…`. It resolved, `latem doctor --secrets` reported `[ ok ]`,
and the build received a key that is not a key. The failure surfaced two minutes
into the next release build, as a 401 from `fastlane pilot upload` — the exact
failure the App Store Connect check exists to prevent, arriving from the one
place that check does not look.

**If you are on v0.1.0 and keep a PEM in the Keychain, that secret is not
reaching your builds intact.** Upgrading is the fix; nothing needs re-storing.

The provider now reads `security -g`, which marks an encoded value `0x<HEX>`,
and decodes it. `-w` could not be salvaged: the encoding is unmarked and
therefore ambiguous — a secret whose literal value is `deadbeef` and one whose
value is the four bytes `DE AD BE EF` print identically under it, so any
heuristic that decoded the second would corrupt the first.

Two smaller fixes came with it. A secret larger than about 2.4 KiB would have
been truncated rather than decoded, because `-g` renders the bytes as hex *and*
again as an escaped string and the capture was bounded at 8 KiB. And output that
cannot be parsed is now an error rather than a silently wrong secret.

## Documentation

`latem run myapp test` is four commands away from `curl | sh` in the README, and
an acceptance run in a fresh macOS account established that following only the
README does not get you there. Twelve gaps are fixed in this release, including
four cases where copying the README's own example produced an error:

- The `caches:` example was **rejected as written**. A job's `caches` is a list
  of names referring to a top-level `caches:` block that the README never
  mentioned. Both examples are corrected and are now checked against the parser.
- Giving the machine a **git credential** and authoring, committing and pushing
  **`.latem/jobs.yaml`** are now steps rather than assumptions. Each of them
  blocks a clean machine on its own.
- `runs_on` in the job example could not be scheduled by the config `latem init`
  writes; the mismatch is now stated.
- Newly documented: where secret values live and why a multi-line one needs the
  Keychain or a `[secrets.commands]` entry; `latem list --all`, without which a
  finished run is invisible; `artifacts:`; the twelve run states, three of which
  are not `failed` although all three exit `1`; and that bare `latem run` exits
  `0` for "queued", so anything checking a result wants `--wait`.

`docs/acceptance.md` §7 has the full result and `docs/acceptance-pass1-findings.md`
has all twenty findings verbatim. Seven remain open, all cosmetic or
message-quality, none blocking a first run.
