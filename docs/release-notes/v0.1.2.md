## What changed

**Nothing about how a build runs.** Every fix here is in what latem *tells* you
— `doctor`'s diagnoses, a step's log line, two listings. If v0.1.1 is building
your app correctly it will carry on doing so, and you can take this at your
leisure.

The exception worth reading is the first one.

### `doctor --secrets` could print part of a secret's value

Its contract is "names only, never values". It enumerated names with its own
parser — split each line on the first `=`, report the left side — which is
correct for `KEY=value` and wrong for every line of a quoted multi-line value,
whose interior lines are value and frequently contain `=`. Given a PEM in
`secrets.env` it printed one of the key's own lines as though it were the name
of a secret:

```
[FAIL] secret / QQQQINTERIORLINETWOQQQQ  file: …: line 2: unterminated double quote
```

This is `doctor`'s output rather than a run log, and the redactor was never
involved — it is not a bypass, and nothing reached a broker or a build log. But
it is the one command that promises never to do this, and it was the only way it
ever had. The second parser is gone: `doctor` now enumerates with the parser
resolution uses, a file that does not parse yields **no** names and one failure
naming a line number, and that error never carries line content.

A side effect worth knowing: `doctor` now lists what the agent could actually
resolve. The old reader accepted `export KEY=` and skipped malformed lines, while
the real parser rejects such a file outright — so it could list names that could
never resolve.

### `doctor` said why a repository refused, for the wrong reason

The repo check reported the first line of `git ls-remote`'s output. ssh writes
`Warning: Permanently added 'host' (ED25519) to the list of known hosts.` on
success, so on a machine seeing a host for the first time — exactly the machine
this check is for — it announced a known-hosts warning as the failure while
`Permission denied (publickey)` sat two lines below, unread. Its explanation was
a fixed paragraph about launchd not inheriting an ssh agent, attached to every
failure whatever the cause, and flatly wrong for `Repository not found`, where
the credential worked.

The detail is now the first line that is not ssh progress. The explanation
follows the cause — no key, a repository that answered but not to this key, an
unverified host key, name resolution, an https helper, a refused connection —
and where the cause is specific enough, `fix` is a repair rather than another
diagnostic: a missing key answers `gh auth login --git-protocol ssh` instead of
`git ls-remote` a second time.

### Smaller, in the same vein

- **`doctor --fix` listed prose among its commands.** Two of eight lines on a Mac
  failed if pasted, one of them the remedy for the only failure. Steps a person
  performs now print under their own heading, "By hand — these are not commands".
- **A killed step was logged as "finished".** A cancelled or timed-out step
  closed with `finished in 3.854s` — time spent waiting to die — contradicting
  the run-level line two lines below. It now reads "cancelled after" or "timed
  out after". A non-zero exit still says "finished", because it did.
- **`latem service status` ended in a dangling brace.** It printed the first line
  of `launchctl print`, which is the opening of a brace block. It now summarises
  what is inside: `state = running, pid 4242`, or the last exit code for an agent
  that is loaded and stopped.
- **`latem cache ls` emitted a padded blank row and said "1 caches".** The
  trailer went through the tabwriter. It is now a blank line and a sentence.
- **The App Store Connect check contradicted itself**, listing all three names as
  both resolving and not resolving when a backend errored. Three states now have
  three disjoint lists.

### Documentation

The README's install line pointed at v0.1.0 while the secrets section, two
hundred lines below, warned that v0.1.0 silently corrupts a Keychain-held PEM.
Install now names the current release. The `latem list` sample was missing the
`#` column, which is the build number a job reads as `$LATEM_BUILD_NUMBER`; both
are corrected, and `#` is now documented rather than merely present.

### Under the hood

Every GitHub Action this repository uses moved to the node24 runtime, and an
intermittent test failure in the remote broker's sink is fixed — it awaited an
in-memory counter and then read the store on the next line, which is a race the
design deliberately allows.
