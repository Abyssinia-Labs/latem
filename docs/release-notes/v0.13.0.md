## What changed

**A checkout no longer fails because another job was fetching the same
repository** (RUNNER_SPEC A112). Jobs of one repository clone their workspace
out of a shared mirror, and until now only fetches took its lock. A clone that
ran beside a fetch, or beside the detached `git maintenance` that git 2.54
starts after every fetch, could miss a pack that was repacked away under it and
fail with `fatal: unable to read tree`. A clone now holds the mirror's lock
shared, and fetches, the LFS fetch and the mirror's gc hold it exclusive, so
clones of one repository still run side by side. Mirrors and workspaces no
longer run maintenance on their own. A lock wait cut short by the run ending is
`E_SOURCE`, retryable as before.

**The Docker daemon's address is `[docker] host` in `config.toml`** (A111).
Every Docker client latem builds (the docker executor, the caches, doctor,
setup, capacity and `latem cache`) now looks at `[docker] host`, then
`DOCKER_HOST`, then the system socket. A native step is given the address as
`DOCKER_HOST`, beneath `[runner.native] env` and the job's own env, so a macOS
job that builds images with Colima or OrbStack reaches the same daemon. Nothing
about Docker goes in the LaunchAgent or unit any more. `latem setup` finds an
engine's socket (the docker context's, then Colima's, OrbStack's, Kiri's,
Rancher Desktop's and Docker Desktop's usual places) and writes it, with a
linux runner sized from that daemon. Only Unix sockets are accepted.

**Linux jobs with JavaScript actions no longer fail with exit 127 after an
image changes** (A109). The tool cache volume is now one per runner and image,
`latem-toolcache-<runner>-<image id>`, filled by latem before the run's
container exists and marked complete last. A volume without the mark is emptied
and filled again. Volumes of images since rebuilt or removed, and the old single
`latem-toolcache-<runner>` volume, are removed for you. doctor's
`toolcache.<runner>` says whether the next run's volume was filled to the end.

**`latem vault` runs latem-vault** (A110). `latem vault <args>` finds the
vault's command where A104 looks and runs it with the same arguments. A machine
that reads the vault and has no vault command gets the readiness item
`vault-install`, which installs it from the Abyssinia-Labs tap with Homebrew.

## Upgrading from v0.12

- **Installed with `install.sh`:** run `latem update` once.
- **Installed with Homebrew:** run `brew upgrade latem`.

Either way, the running agent moves onto the new version at the first moment no
build is in flight.

**If you added `DOCKER_HOST` to the agent's LaunchAgent or unit by hand**, run
`latem service install` once after upgrading. It moves that address into
`[docker] host` before it rewrites the definition, so Docker keeps working.
Until you do, doctor's `service.docker_host` warns about it. Running `latem
service install` on v0.12 would have dropped the line; on this release it is
safe.

Nothing else needs you. The first Linux run after the upgrade fills a new tool
cache volume, which takes a little longer once.
