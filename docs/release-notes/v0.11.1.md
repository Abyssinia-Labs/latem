## What changed

**The agent notices a dead control-plane connection** (RUNNER_SPEC A98). A
connection that stops answering without closing, as when a network path
drops packets instead of refusing them, used to stay open until TCP gave up,
about fifteen minutes later. Meanwhile latem-cloud showed the machine
offline and held every job meant for it. The agent now pings the control
plane every 15 seconds and gives a connection up after 30 seconds with no
frame and no answered ping from it, or when a frame cannot be written within
30 seconds. It dials again about a second later, inside latem-cloud's
45-second offline rule, and logs why, once:

```console
level=WARN msg="no frame from the control plane in 30s, reconnecting" url=wss://gw.latem.dev/agent
```

On a healthy connection that line should be rare. The pings are WebSocket
control frames, which the control plane already answers, so latem-cloud
needs no change and the wire protocol is still 2.9.

### Upgrading from v0.11.0

- **Installed with `install.sh`:** run `latem update` once.
- **Installed with Homebrew:** run `brew upgrade latem`.

The running agent moves onto the new version at the first moment no build is
in flight. Nothing else changes: `config.toml` and `state.db` are read as
v0.11.0 left them.
