## What changed

**A job can download what an earlier job uploaded** (RUNNER_SPEC A84,
protocol 2.9). `actions/download-artifact` reads what was uploaded by a job
it needs, directly or further up, called workflows' jobs included. The
artifact never leaves the machine that made it. latem.dev runs the
downloading job on the machine that ran the uploading job, and that machine
reads the files from its own store.

- A download matches an upload when both names are known and equal, or when
  either is only known as the job runs. A download with no name reads every
  artifact.
- If the jobs it reads ran on two machines, it fails and names them. It also
  fails, saying why, if that machine is lost or removed, or has no runner for
  the job's labels. While the machine is offline, or its runner is busy, the
  job waits for it.
- `runner.temp` works on Docker runners for uploads and downloads. The files
  are copied out of and into the container.
- `latem workflows check` prints `artifacts from build: runs on the machine
  that ran them` under such a job. `latem try` warns that a try runs one job,
  so its download finds only what that job uploads.

Still refused: a download that no earlier step and no job it needs could
satisfy (A77). An upload inside a composite action is not seen.

**`actions/checkout` takes `sparse-checkout` and
`sparse-checkout-cone-mode`** (A83), with actions/checkout v6's meaning.
Cone mode is on unless the step turns it off. A later checkout with no
patterns brings the whole tree back. Both inputs must be known when the job
is compiled, and a sparse checkout needs git 2.35 or later in the job's
environment.

A checkout input that names a value only known while the job runs
(`steps`, `job`, `runner` or `secrets`) is now refused by name. It used to
be compiled as if it were empty.

**A cache path under `~` works on Docker runners** (A38). `actions/cache`
with `path: ~/.cargo/git` used to fail before the first step with
`E_CACHE: … is not an absolute path`. `~` is now the home the job's steps
run with in its image. An image whose user has no home is refused by name.

### Upgrading from v0.5.0

- **Installed with `install.sh`:** run `latem update` once.
- **Installed with Homebrew:** run `brew upgrade latem`.

Either way, the running agent moves onto the new version at the first moment
no build is in flight.

**The wire protocol is 2.9, and latem.dev already speaks it.** A v0.5.0
machine keeps working as before. Update every machine anyway: a job that
downloads artifacts runs only on 2.9, and only on the machine that ran the
uploading job. If that job ran on a machine still on v0.5.0, the downloading
job waits for it to be updated. On latem.dev, a job that has waited 72 hours
for a machine fails, saying what it waited for.
