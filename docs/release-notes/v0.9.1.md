## What changed

**A job that fails on biome now says where** (RUNNER_SPEC A93). v0.9.0 gave
every run a result with its errors by file and line, and its biome reader took
only the linter's. A job that failed on `biome check` over one file that was
not formatted came back as a failed step with 0 errors. Now every diagnostic
biome prints is read:

- **A file the formatter would change.** Biome names the file and no line, so
  the problem has a `file` and no `line` or `column`. A program that maps
  problems to places has to take a file alone.
- **A syntax error**, at its line and column.
- **`biome ci` in colour.** Where `GITHUB_ACTIONS` is not set, it colours what
  it prints even into a pipe, with a terminal link around each rule's name,
  and v0.9.0 read none of that. Links are now dropped before a line is read,
  as colours are.

**A problem said twice is counted once.** In a workflow's job, `biome ci`
writes each problem as an `::error` command and again in its own report, and
v0.9.0 kept both. When a step's own `::error` and a reader's problem have the
same file, severity and line, and the same message or code, the result keeps
the reader's, which has the tool's fix. A step's own `::error` that no reader
found is kept, as before.

### Upgrading from v0.9.0

- **Installed with `install.sh`:** run `latem update` once.
- **Installed with Homebrew:** run `brew upgrade latem`.

Either way, the running agent moves onto the new version at the first moment
no build is in flight.

**Results already written stay as they are.** A run's result is read off its
log as the run goes, by the agent that ran it, so only runs after the upgrade
get the new reading. Their logs are unchanged, and `latem logs` still has
everything.

Nothing else changes. The wire protocol is still 2.9, and v0.9.1 leaves
`state.db` as v0.9.0 left it.
